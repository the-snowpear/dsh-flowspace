# P2 内容流实施子计划

P2 对应 E12–E20、E29–E30、E49–E52。验收流程从一段文本开始，将其拆成条目，每条分派给一个独立的 Agent，会合后按原顺序输出结果。实现基于 P1 的类型化端口、Host 执行器、运行记录和 QuickJS worker。

## 实施顺序

以下源码路径相对于 `packages/flowspace/src/`。每项开工前在当前工作树按相对路径备份，结束时运行 `pnpm check`，涉及 Host 时运行 `pnpm test:integration`。前端沿用总计划的四种视图验收。使用已发布的 DSH 0.2.2-rc.3，代码和模板均由用户确认后再提交。

## 实施约定

- P2 交付常量和运行内累积。P3 将累积对接变量日志，P6 在玩法模板中复用常量节点。
- 携带原生条目 ID 的来源优先使用该 ID。文本条目用内容哈希及相同值的出现序号区分泳道，新增或移动其他值时保留原有身份。
- 新建产出线默认为“结束时发”。支持流式输入的端口可设为“随出随发”。两种模式均保留条目来源和顺序。
