# FlowSpace 画布扩展：控制流、数据流与触发（讨论结论 · 草案）

本文记录 2026-11-20 多轮产品讨论的结论：给画布加入条件判断、内容流（扇出）、触发器、状态事件、执行节点、人工交互、玩法、数据变换、可变变量与节点注册表等能力。**全部为草案，尚未实现**。落地时需对照 [设计规范](design.md)、[决策台账](product-decisions.md) 与 AGENTS.md 的工程约束：调度驻留 Host、编辑态与运行态分离、撤销不重放请求、边界单点校验。

编号使用 `E` 前缀，避免与台账中的 `M` / `D` / `R` 冲突。

---

## 一、设计总纲

扩展能力建立在三个内核部件之上，具体节点在其上批量扩展：

1. **多输出端口 + 跳过令牌**：所有分支类能力的基础。
2. **类型化端口**：内容流（扇出、拆分、合并）的基础。
3. **容器读写口 + 引用权限**：Agent 修改看板等资源的基础。

执行类节点（终端、Git 操作等）统一遵循第九节的**执行节点通用方法**。

动机示例：内置 TDD 闭环模板（`templates.ts` 中 `etdd-loopback` / `etdd-exit`）当前没有退出条件。`emitDownstreamTokens` 会向所有出边发令牌，验证员即使判定通过，回环仍会跑满 `maxRounds`。条件分支与终端执行节点用于补上这一缺口。

## 二、判断节点与分支

| 编号 | 结论 |
| --- | --- |
| **E01** | **判断节点三类**，共用外形：一个输入、多个命名出口，外加一个固定的「出错」出口。<br>① **条件节点**：可视化规则（字段 + 运算符 + 值，支持且/或），不跑代码、不调模型。字段可取上游结论、退出码、改动文件数、token 用量等。<br>② **代码节点**：表达式/脚本在独立 worker 的 QuickJS WebAssembly 实例中执行。Host 传入输入快照的 JSON 副本，脚本返回分支 ID 或布尔值。每次判断创建独立的 runtime/context，默认内存上限为 32 MiB，并设置栈限制、执行中断和 worker 硬超时。工作流脚本只能使用引擎内置的 JavaScript 接口。原定的「命令模式」已并入终端执行节点（E38）。<br>③ **AI 判断节点**：单次模型请求，不建对话（E28）。从 DSH 已有供应商/模型中选择；每个分支写标签和说明，模型返回分支、理由与置信度；可设「置信度低于阈值走人工」。<br>④ **人工判断**：即人工选择节点（E41），由用户点选项按钮决定走哪个出口。 |
| **E02** | 导入的工作流若含代码节点，导入时需用户确认。 |
| **E03** | **跳过令牌**：未选中的出口发跳过令牌，沿下游传递；汇合节点收到跳过即不再等待该路径（死路径消除）。`liveTokenProducers` 需由静态可达性改为随运行动态更新。 |
| **E04** | **线上简单逻辑**，不单独成节点：取反、从第 N 轮起生效、最多 N 次、延迟触发。复杂路由使用判断节点。 |

## 三、端口类型与连线

| 编号 | 结论 |
| --- | --- |
| **E05** | 端口类型：文本、列表、结构化记录（JSON）、信号、文件，以颜色区分。 |
| **E06** | **接续线严格校验类型；其他线宽松**，类型不符时自动转为文本并给出提示。 |
| **E07** | 连线职责：**谁能看/谁能改** → 引用线（资源指向使用者，权限写在线上）；**什么时候跑** → 接续线（严格）；**产出流向哪里** → 数据流线（生产者指向容器或下游）；**发生了什么** → 事件线（见第六节）。 |

## 四、容器读写：授权与投递

| 编号 | 结论 |
| --- | --- |
| **E08** | **引用即挂载（授权）**：容器（看板、便签、文件）→ Agent 的引用线带权限档位：**只读**（默认，即现有行为）/ **可推进**（勾选、移列、评论）/ **可编辑**（增改删），每档可叠加「每次询问」（复用 DSH 原生审批）。授权范围与引用范围一致（单卡引用即只能改该卡）。仅持有可写授权的 Session 获得对应工具（如 `board_*`），注册方式与 `team_delegate` 相同。改动发生时沿线反向闪动，被改条目标注作者 Agent。不新增端口。终端、Git 等执行节点不使用档位授权，改用 E34 的「工具调用」形态。 |
| **E09** | **投递**：Agent → 容器写入口的数据流线。Host 在回合完成时按规则写入（每行一卡 / 整段一卡 / 解析清单），Agent 无需任何工具，结果确定。授权与投递是两种形态：前者由模型随时决定，后者由 Host 按规则写入，不是读写权限的差别。 |
| **E10** | Agent 对容器的改动**不进入用户撤销栈**，单独记入「Agent 改动记录」，可逐条撤回。 |
| **E11** | **并发编辑**：容器写入以单个条目为单位，带版本号，**用户编辑优先**；Agent 写入冲突时失败，工具结果返回冲突信息，Agent 可读取最新内容后重试。 |

## 五、扇出与合并分拣

| 编号 | 结论 |
| --- | --- |
| **E12** | **扇出节点由 Host 执行**。不接扇出节点时，列表整体传给下游（取消线上的「整体/逐项」开关）。 |
| **E13** | **扇出与合并分拣成对出现，像一对括号**。用户只搭一条母版泳道（扇出 → 若干节点 → 合并分拣），Host 按条目复制泳道，放入扇出组（复用现有分组/组合节点 D19，折叠后显示进度）。括号内为流式（各泳道独立推进），括号外为批式。若扇出节点原本连有下游，自动改为「扇出 → 泳道 → 合并分拣 → 原下游」，记为一步撤销。 |
| **E14** | **泳道生成与更新**：静态来源（看板、文件列表等）连好后，泳道随条目数量实时增删（草稿泳道，不创建 Session）；动态来源（上游 Agent 输出）运行前显示母版泳道与「×?」占位，运行时生成。上游以「随出随发」方式输出时（E29），每到一项开一条泳道。运行开始时 Host 将静态条目列表固化为快照，运行期间来源变化只影响下一次运行。 |
| **E15** | **泳道身份**：绑定条目稳定 key（看板卡片 ID；文本条目用内容哈希），不按序号。条目减少时：运行前直接删除对应泳道；运行后变灰并标记「已移出」，可手动清理。 |
| **E16** | **复制泳道同步方式可配置**，默认跟随母版，单独修改过的泳道标记「已覆盖」并停止同步（与模板同步 R1 同机制）。 |
| **E17** | 超过 10 条泳道自动折叠，点击展开；并发上限在扇出节点上设置。 |
| **E18** | **生成节点例外**：Host 生成的节点带 `generatedBy` 标记，整批生成算一次文档变更；撤销只移除画布节点，不删除 Session、不重放任何请求。这是「运行态与文档分离」原则的明确例外。 |
| **E19** | **合并分拣节点**：合并部分设等待策略（全部 / 任一 / 法定数）和输出形式（列表 / 拼接文本）；分拣部分可选，开启后增加出口（通过 / 未通过 / 出错），规则复用 E01 三种判断方式。策略为「任一」时，其余分支**默认不取消**，跑完后标记「结果未采用」；可选「取消其余分支」。 |
| **E20** | **泳道会话放置**：泳道使用顶层 Session（需要每轮 Changes），命名为「扇出组名 #n · 条目标题」，并通过原生 `sidebar.session.row.trailing` / `.hover` 插槽显示组标记（如「组名 3/12」）与整组列表。rc.3 原生侧栏只能按工作区分组，不支持会话文件夹；在侧栏搜索组名即可列出整组，作为虚拟文件夹。不采用「每组一个子目录工作区」（违反 M05）或「泳道改为子会话」（侧栏不可见且无 Changes）。上游若提供会话分组能力再切换。 |

## 六、触发器、状态端口与事件线

| 编号 | 结论 |
| --- | --- |
| **E21** | **触发器节点**：定时/间隔、文件变化、Git 事件、终端事件（非零退出、输出匹配）、容器事件（卡片进入某列）、启动台（按钮 + 可选表单）。只有一个接续类型出口；节点显示启用状态、下次与上次触发时间。触发内容可为列表（如变化文件），可直接接扇出。 |
| **E22** | **定时触发器由 FlowSpace Host 自行调度**（目标是启动一次 Run，不是向 Session 投递指令），复用 `dsh-util-time` 的 Cron / RRULE 解析，与原生 `dsh-schedule` 写法一致。原生 Schedule 重启后会补发最近一次错过的投递，而本方案默认不补跑，需在界面上说明这一差异。 |
| **E23** | **自动触发护栏**：冷却与每日上限、上次未结束时的策略（跳过 / 排队 / 打断，默认跳过）、Host 离线期间错过的触发默认不补跑并显示次数。这三项既可在节点上配置，也可在画布设置中设全局默认；画布顶栏提供**自动触发总闸**；导入对话框（`WorkflowImportDialog`）提供「导入后启用触发器」选项，默认不勾。 |
| **E24** | **运行来源**：`FlowspaceRun.origin` 新增 `trigger`，记录触发器节点；运行总览支持按来源筛选，并显示来源标记。 |
| **E25** | **状态端口**：位于节点**顶部居中**，与底部居中的子代理端口对应。适用于 Agent、团队、终端、Git、扇出组、判断节点；便签、文件等纯内容节点不设。未连线时隐藏（R8）。 |
| **E26** | **事件线**为第三种用户连线，可连到接续入口、判断节点、容器写入口、通知节点和解析节点。细线按事件类型着色（出错红、等待琥珀、完成绿），触发时闪过一次短脉冲，与接续线的持续流动区分。 |
| **E27** | **事件线的发送方式逐条配置**：**结束触发**（按结束原因过滤）/ **变化触发**（勾选关心的状态切换）/ **连续**（推送输出增量、工具调用、token 计数，可设节流）。连续方式只能连到不调用模型的节点；事件线连 Agent 必须设冷却。Host 检测自触发环路，并要求环路设置冷却与次数上限。<br>**事件内容**：默认是轻量信封，包含节点/运行/轮次标识、事件类型与 `TurnEndReason`、时间、token/耗时/步数、错误或输出摘要（截断），以及 `sessionId + seq` 指针。下游按 `seq` 取完整内容，与 R3 的 `atSeq` 快照原则一致。线上提供「附带完整内容」开关，超过 64 KiB 沿用 spill 规则；连续方式附带自上次推送以来的增量。 |

## 七、模型请求与结构化输出

| 编号 | 结论 |
| --- | --- |
| **E28** | **AI 判断为单次请求，不建对话**：通过 `ctx.llm.stream({ provider, model, messages, purpose })` 发起，声明 FlowSpace 自己的 `purpose`；供应商列表取自 `ctx.llm.listProviders()`。rc.3 的 `GenerateOptions` 没有 `tool_choice`，因此要求模型输出 JSON（分支、理由、置信度），由 Host 校验：失败重试一次，仍失败则走「出错」出口。请求不进入任何 Session 日志，判断的输入、输出、模型与 token 记入运行记录。E36 中的「AI 生成」参数沿用同一机制。 |
| **E29** | **结构化输出 `flow_emit`**：Agent 的输出连到需要列表或结构化输入的节点（扇出、合并分拣、数据类节点、带「上游提供」参数的执行节点）时，Host **自动注入**条件工具 `flow_emit`，机制同 `team_delegate`。每条输出线可配置：**随出随发**（每次调用立即发给下游）/ **结束时发**（暂存，回合正常完成后一次发出；多次调用默认追加）。随出随发只能接扇出、合并分拣和数据类节点。回合结束仍未调用时，先自动解析输出中的 Markdown 列表或 JSON 代码块，作为兜底而非主要方式；解析失败则发出错事件，卡片提供「提醒补交」按钮，不自动重试。 |
| **E30** | **上下文解析节点**：从文本或事件流中提取 TODO、文件路径、报错堆栈、JSON/代码块等，输出列表，可接扇出、看板或判断节点。提取规则复用 E01 三种方式。 |

## 八、通知与原生消息线

| 编号 | 结论 |
| --- | --- |
| **E31** | **通知节点**：rc.3 没有原生系统通知（`dsh-client-ui-account-notifications` 为服务端账号公告，不可用）。采用组合方式：应用内提示通过 `workspace.toast` 注册 FlowSpace 提示类型（接口待验证）；系统通知由 FlowSpace 前端调用浏览器 Notification API（需用户授权一次）；提示音可选。 |
| **E32** | **原生消息线锚点**：改为**从两节点的几何中心相连**，沿用现有的弧线与路由逻辑，节点内部的线段被卡片遮挡、不显示，从而让出顶部与底部居中的端口位置。落地时需同步修订 design.md §3.2 中「从卡片上下边缘进出」的表述。若卡片半透明导致露线，改用裁剪而不是依赖遮挡。 |

## 九、执行节点通用方法

适用于所有「执行一个确定操作」的节点：终端执行节点、Git 操作节点，以及以后的同类节点（如 HTTP 请求）。前面的 `flow_emit`（E29）是同一方法在数据输出上的体现。

| 编号 | 结论 |
| --- | --- |
| **E33** | **工具节点的两种角色**：**资源角色**用引用线向 Agent 提供快照（屏幕、diff 等，即现有行为）；**执行角色**有接续入口与出口、顶部状态端口和「成功 / 失败」出口，由 Host 执行确定的操作，再把结果交给下游。 |
| **E34** | **节点定义操作，线型决定调用方式**。<br>· **接续线进入节点 = 触发执行**：由 Host 在上游完成时执行，时机确定，一定会执行（除非被判断节点分走）。<br>· **引用线从节点连到 Agent = 作为工具交给 Agent**：Agent 自行决定是否调用、何时调用、调用几次；工具受节点定义约束（如终端只能执行预设命令、只能填允许的变量；Git 只能执行节点选定的操作），不是自由输入。<br>两者的区别不在能否携带参数，而在由谁决定做不做、什么时候做。 |
| **E35** | **参数来源**：节点的每个参数单独设置来源：**固定值** / **模板**（插入上游变量，必须转义，防止命令注入）/ **上游提供** / **AI 生成** / **人工填写**。 |
| **E36** | **参数预取**：触发模式下若有参数设为「上游提供」，Host 在**上游回合开始时**（而非触发时）通过 `agent/pre-step` 注入对应工具（如 `provide_commit_message`），并附说明「本回合结束后将自动执行该操作，请在结束前提供参数，不要自行执行」。Agent 在回合中提供的值由 Host 暂存，回合正常完成后用于执行。<br>**兜底顺序默认 1 → 2 → 4**：① 上游提供 → ② AI 生成（单次请求，依据本轮 diff 与上游结论，模型可选，E28 机制）→ ④ 停下等用户填写（可编辑的放行框）。③ 模板与「追问上游」（向持久会话补发一轮，代价是多一轮）为可选项。**必填参数缺失时绝不带空值执行，也不静默卡住。** |
| **E37** | **执行权限**：固定值参数视为用户预先批准，免确认；模板参数做转义；上游提供或 AI 生成的命令/操作默认每次确认（复用 confirm 放行界面，执行前展示完整内容），可配白名单免确认。**若直接发出该命令的那个节点所在会话处于完全访问模式，则跳过确认**，只看这一个节点，不看整条链路；命令不来自会话（触发器、文件来源等）时按节点自身配置。执行不经过任何 DSH Session 的审批流程，因此由 FlowSpace 负责把关；是否提供 `dsh-bash-sandbox` / `dsh-pwsh-sandbox` 沙箱执行选项，待核实接口。 |
| **E38** | **终端执行节点**：两种模式。**一次性执行（默认）**：经 `ctx.subprocess` 在所属 worktree 运行，取得准确退出码与 stdout/stderr，可设超时。**交互终端**：向长期运行的终端发命令（M09 二期 `attach`），以结束标记或「输出匹配即就绪」判断完成，适合 dev server 等不退出的进程。输出：文本（过长截断并 spill，可切换为按行输出的列表）、退出码/耗时/超时（状态端口）、「成功 / 失败」出口。代码节点的命令模式并入此节点；终端不再提供「可输入」档位授权。 |
| **E39** | **Git 操作节点**：独立于现有 Git 面板节点。操作复用现有 `GitActionRequest`（暂存、提交、建分支、切换分支、fetch、pull、push、建/删 worktree 等），参数按 E35–E36 取得。工作目录默认跟随上游 Agent 的有效工作目录（扇出泳道可能分属不同 worktree），也可固定到某个 worktree。写入经 `HostGitService` 的写队列与 `expectedRevision` 校验。discard、push、删除 worktree 默认确认；切换分支在该 worktree 还有其他会话时也需确认（会影响同一目录中的其他会话），仅一个会话使用时免确认。权限规则同 E37。输出结果文本（如提交 oid）与「成功 / 失败」出口。 |
| **E40** | **观测线**：Agent 通过原生 bash/终端工具执行的命令（含 git）不受画布连线约束，Host 从 Session 事件中观测，并在该 Agent 与对应的 Git/终端节点之间画**只读的观测线**（虚线），原则同 M11。授权线由用户绘制，代表 FlowSpace 提供的受控通道；观测线由系统绘制，代表原生工具实际做过的操作。另可提供节点开关「仅限画布授权」，利用作用域工具限制移除原生 bash/终端工具（已验证主管作用域可限制工具），粒度较粗。 |

## 十、人工交互节点

| 编号 | 结论 |
| --- | --- |
| **E41** | **人工节点四类**：<br>① **人工选择**：给出选项按钮，每个选项一个出口，作为判断节点的第四种（E01④），共用外形。<br>② **表单**：文本、数字、下拉、勾选等字段，输出一条结构化记录；E36 兜底顺序中的「停下等用户填写」使用同一界面。<br>③ **打分 / 评审**：对上游产出打 1–5 分或点赞并附评语，可接条件节点（如低于 4 分回到上游），也是擂台类玩法的基础。<br>④ **审阅编辑**：把上游内容放入编辑器，用户修改后传给下游。<br>不单独做「检查点」节点，由 confirm 线承担。数据格式沿用原生 `ctx.userQuestions` 的约定（选项、自定义文本、跳过的表示方式），界面由 FlowSpace 绘制在画布上；人工问题**不出现在**上游 Agent 的原生对话中。 |
| **E42** | **通用规则**：可用引用线把上游内容接入人工节点直接展示，并附说明文字；待处理时在节点卡片、视口边缘方向提示（D32）和运行总览「等你处理」中提醒，也可经状态端口接通知节点。**超时可配置，默认一直等**，可设置等待时长，到时后跳过（亦可选走默认选项或单独的「超时」出口）。扇出泳道中的人工节点提供**批量处理视图**（表格逐行回答，可整列套用同一答案）。可选「AI 预填」（单次请求给出建议答案，用户确认或修改），默认关闭。待处理问题记入运行记录，Host 重启后保留，不自动代答（同 D42）。 |

## 十一、玩法

大部分玩法由现有部件组合而成，以**内置玩法模板**提供；只新增少量基础件。

| 编号 | 结论 |
| --- | --- |
| **E43** | **运行回放**：按运行记录中的图快照（`run.graph`）渲染，而非当前画布；底部时间轴可拖动，支持 1× / 4× / 16× 速度，镜头跟随运行中的节点。纯渲染、只读，不驱动执行。需为令牌补充就绪、放行、消费的时间戳（目前只有 `source.capturedAt`）。 |
| **E44** | **断点调试**：节点可设断点；令牌即将被消费、Host 发出请求前（`enqueue` 中 `runtime.send` 之前）暂停，展示组装好的完整输入（任务、来源快照、注入的工具）。操作：继续 / 单步（跑完本节点后在下一节点前再停）/ 跳过。可仅对本次修改输入，不改变节点保存的任务。 |
| **E45** | **预算闸门**：做成设置加状态事件，不单独做节点。运行级与节点级均可设 token、时长、轮数上限；超出时暂停运行并发出「超出预算」事件。画布顶栏显示实时消耗表。 |
| **E46** | **新增基础件**：① **泳道参数绑定条目字段**——母版泳道中节点的模型、人设、工作目录等配置可绑定到当前条目的字段；② 合并分拣新增「**择优**」策略——按 AI 或人工分数取最高项交给下游；③ **常量节点**——手写文本或列表；④ **随机节点**——从分支或选项中随机选取，可设种子以便复现，也支持轮询分配。 |
| **E47** | **内置玩法模板**：**模型擂台**（常量模型列表 → 扇出、泳道模型绑定条目 → 合并分拣「择优」）、**模型陪审团**（多模型投票 → 合并分拣法定数；DSH 为本地单用户，由模型投票）、**辩论**（两 Agent 成环接续、设轮数上限 → AI 判断裁决）、**头脑风暴墙**（多人设 Agent 往同一看板追加点子 → 打分节点投票 → 高分点子进入实现）、**随机灵感**（随机节点抽取人设或风格 → Agent 创作）。 |
| **E48** | **战绩榜**：跨运行统计各模型在擂台中的胜负，可按任务标签筛选。**运行战报卡**：运行结束后用单次请求生成总结卡（用时、token、轮数、表现最好的节点、产出物），可导出为图片。两者都做。 |

## 十二、数据变换节点

| 编号 | 结论 |
| --- | --- |
| **E49** | **原则**：规则与代码类变换在 Host 内即时完成，不调模型、不花钱；代码沿用代码判断节点的隔离 worker 与超时；需要 AI 的变换一律用单次请求，不开会话。**节点清单**：拆分（文本 → 列表：按行、分隔符、正则、Markdown 标题、代码块）、合并（列表 → 文本：连接符、编号列表、逐项套模板）、提取（正则、JSON 路径、代码块、指定标题下的段落）、模板（多个命名输入端口，`{{名字}}` 拼接）、映射（逐项变换：模板 / 代码 / AI）、过滤（复用判断节点三种方式）、排序（字段 / 规则 / AI）、去重（精确 / 规范化 / AI 语义）、常量（E46）、累积（E56）。 |
| **E50** | **AI 映射是轻量扇出**：每项一次单次请求，适合改写文字；需要动手干活（工具、改代码、Changes）时用扇出泳道。 |
| **E51** | **实时预览**：输入为静态来源（看板、便签、常量、文件）时，连好即在节点上显示结果预览，上游变化时随之更新；连线上显示条目数。AI 模式不自动预览，只提供「试运行」按钮。 |
| **E52** | **规模上限**：列表默认最多 1000 项，超出时提示并截断，可在设置中调整；单项超过 64 KiB 沿用 spill 规则。 |

## 十三、全局可变变量

| 编号 | 结论 |
| --- | --- |
| **E53** | **原则调整**：capabilities.md §3.1「不将文本快照伪称为可变共享内存」原意是不误导模型，而非禁止可变状态。现调整为：**可变状态可以有，但必须显式、带版本、可追溯；传给 Agent 的值标明是哪个版本的快照。** 原文件暂不修改。 |
| **E54** | **定义与当前值分离**：变量定义（名字、类型、初始值、作用域）存于可编辑文档，可撤销；当前值属于运行态，存于 Host 运行存储，不进撤销栈，可一键重置为初始值。**作用域**：运行级（默认，每次运行重置）/ 画布级（跨运行保留）/ 泳道级（每条扇出泳道各一份）。**类型**：文本、数字、布尔、列表、记录。 |
| **E55** | **写入**：① 赋值节点（设置、追加、自增 / 自减、合并记录），由 Host 执行；② Agent 工具——变量节点经引用线连给 Agent 并授予可写权限（同 E08），Agent 获得 `var_get` / `var_set`，写入可带版本号做比较交换，版本不符则失败；③ 投递（同 E09）；④ 人工在变量节点上修改或经表单写入。所有写入在 Host 中串行执行（沿用 `transact`），原子操作不丢更新。 |
| **E56** | **读取与追溯**：经引用线或 `{{var.名字}}`（条件节点、模板、终端命令、Git 参数）读取时，Host 在发出请求那一刻固化快照（同 R3 `atSeq` 原则），并附版本号。每次写入记录日志（写入者、时间、旧值 → 新值、所属运行与步骤）；回放可见变量变化，断点时可查看全部变量，变量节点显示最近变化。变量变化作为容器事件发出，可接触发器或事件线（冷却与环路检测同 E23、E27）。画布上以**变量节点**呈现，另有**变量面板**集中查看与重置。**累积节点**保留为快捷方式，内部即向运行级列表变量追加。 |

## 十四、节点注册表

| 编号 | 结论 |
| --- | --- |
| **E57** | **定位**：现有代码中按节点类型写死的分支判断约 106 处，分布在 17 个文件（`CanvasApp.tsx` 占 47 处），新增节点类型成本过高；注册表是本文其余能力落地的前提。**Agent、团队 / 角色、分组保持内置**，不走注册表，它们与会话、调度器、子代理结构耦合过深。 |
| **E58** | **节点定义三部分**：**描述**（前后端共用）——带命名空间的类型名（如 `flowspace/git-op`）、版本、标题、图标、多语言文案、分类（逻辑 / 数据 / 触发 / 人工 / 玩法 / 执行 / 容器）、端口（类型、方向、角色，可按配置动态生成出口）、配置的 zod schema、能力声明（调用模型、执行命令、副作用、风险等级）；**Host 端**——执行器，以及按角色提供的容器读写处理、触发器启用 / 停用生命周期、作为工具交给 Agent 时的工具定义（E34）、参数预取声明（E36）；**前端**——卡片视图（精简 / 展开）、配置表单（默认从 `z.toJSONSchema()` 生成，可自定义）、预览渲染。 |
| **E59** | **执行器约定**：Host 在边界依据描述中的 zod schema 和端口类型校验配置和输入（符合 AGENTS.md「校验放在执行的 Host 边界」），执行器不再重复校验。执行上下文统一提供：单次模型请求（自动记账、计入预算）、限定在所属 worktree 的子进程、节点状态存储、发出事件 / 报告进度 / 取消信号、向用户提问（复用人工节点界面）、spill。抛出的错误自动走「出错」出口；超时与取消统一处理。声明有副作用的节点自动套用 E37 确认规则，重跑时提示。 |
| **E60** | **持久化**：注册表节点统一使用 `kind: "flow"`，`flowType` 保存带命名空间的类型名，`config` 保存配置，`configVersion` 记录配置版本，定义中提供 `migrate` 在读取旧配置时升级。**插件缺失或被卸载时，节点显示为「缺少插件」占位，数据原样保留。** 导出模板附带依赖插件清单（同 `TeamDependencies`），导入时提示缺失的插件。 |
| **E61** | **开放给其他 DSH 插件**：第三方插件注入 `flowspace.nodes` 服务注册节点，前端经插槽注册视图；注册返回释放函数，支持热重载与卸载时自动注销。信任模型与 DSH 插件一致，**安装即信任**，不做沙箱；节点卡片按能力声明显示标记（如「会执行命令」「会调用模型」），确认规则照常生效。注册表 API 带版本号，**先标为实验性**，待内部用它实现三四种节点、接口稳定后再承诺兼容。 |
| **E62** | **迁移节奏**：① 搭建注册表，新节点全部走注册表 → ② 迁移便签、展示、文件等内容节点 → ③ 迁移 Git、Changes、终端等工具节点 → ④ Agent、团队 / 角色、分组保持内置。迁移时顺带把 `CanvasApp.tsx` 中按节点类型分支的代码拆出。 |
