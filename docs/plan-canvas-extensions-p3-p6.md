# FlowSpace P3–P6 实施子计划

四个阶段依次实施，均在当前 Codex 工作树以已验收的 P2 为基线，使用发布版 DSH 0.2.2-rc.3。原计划要求在相应阶段开工前确认本子计划。下表中的源码路径相对于 `packages/flowspace/src/`。

每项开工前列出已有文件并按相对路径备份到 `.backups/`。每项完成后运行 `pnpm check`，Host 改动另跑 `pnpm test:integration`，原生工具注册使用同版 DSH 做 mock 验证。前端全部执行原计划第 3 节。复用现有 DOM/SVG 卡片、检查器、端口、运行总览和对话框，新增样式进入 `client/styles/flow-ext.css`，文案进入 `client/i18n.ts` 的双语 `flow_` 键。每个前端任务交付暗色、亮色、L1 和 0.4 倍截图及 §3.10 六项自检。

## P3 容器与变量

对应 E08–E11、E53–E56。

| 任务 | 改动与实施顺序 | 验收 |
| --- | --- | --- |
| P3.1 授权与内容修改 | 在 `types.ts`、`host/storage.ts`、`core/connect.ts` 记录引用线的权限和询问开关，旧线按只读解析。在 `host/` 接入 `ctx.tools.register(..., { when })`。工具按已绑定的真实 Session 和当前有效连线授权。看板支持勾选、移列、评论和条目增改删，单卡引用限定在该卡。便签编辑和工作区内指定文件的替换使用编辑权限。将每次询问接到 DSH 原生确认，并在确认返回后重查权限和版本。 | 无线或只读会话无法取得写工具。一个普通会话和两个 Agent 并行使用时工具只出现在对应会话。单卡不能改同板其他卡。拒绝、取消、授权撤回、文件版本变化都保持原内容。 |
| P3.2 投递、修改记录与并发 | 在 `core/scheduler.ts` 的正常结束路径处理指向容器的投递线。看板支持逐行、整段和结构化清单，便签和文件按选定内容写入。为步骤与线组合存稳定写入标识。Host 串行校验条目版本，整份画布保存使用基线和用户改动合入最新条目。记录写入者、旧值、新值、版本、运行与步骤，逐条撤回同样校验版本。客户端文档历史按用户编辑重放，接收 Agent 改动时更新当前内容和历史基线。 | 同卡并发修改时用户内容优先，Agent 收到当前版本和可重试的冲突。修改其他卡时互不覆盖。撤销画布编辑仍保留 Agent 改动。历史撤回仅作用于原条目，冷重启后恢复日志且投递不重复。 |
| P3.3 三种变量作用域 | 在文档、工作流导入导出和冻结的运行图记录变量定义及稳定 ID。在 `host/storage.ts` 增加 `variables`，用变量 ID 和画布、运行或泳道的实际作用域键存值、版本与历史。赋值节点支持设置、列表追加、数值增减、记录合并。以同一 Host 写入入口接入投递、`var_get` / `var_set`、人工修改与重置，并把累积节点接到运行级列表变量。启动后才接收对应作用域的值，定义及初值随模板携带。 | 五种类型经真实 RPC 往返。并发追加与自增不丢更新。同名变量在不同运行、不同泳道间隔离，画布级值可跨运行和重启保留。版本冲突与逐次写入记录可查询。 |
| P3.4 快照与画布入口 | 在 `host/runtime.ts`、`core/scheduler.ts`、`core/nodes/data/` 与判断节点的组装入口解析 `{{var.名字}}`，一次发出请求固化值和版本，引用胶囊显示所用版本。线检查器加授权、询问及投递模式。按 §3.6-I 绘制写入反馈与作者头像，按 §3.6-N 复用变量卡片和检查器，提供变量面板、作用域定位、重置及最近五条变化。P5 消费同一容器变化记录，P6 用同一日志回放。 | 变量变动后旧请求仍能查看原快照。完整卡和精简卡能区分值与版本，变量面板操作实际 Host 数据。看板作者、反向反馈与撤回均按线和条目定位。 |

实施约定为同一看板内卡片以现有卡片 ID 定位。文件绑定选中的单个可写工作区文件，用原内容版本检测冲突。便签与文件使用只读和编辑操作，看板使用全部三个档位。兼容旧画布时，以旧线只读、旧条目初始版本和当前已有内容作为读取基线。

## P4 执行节点

对应 E33–E40。

| 任务 | 改动与实施顺序 | 验收 |
| --- | --- | --- |
| P4.1 操作描述与参数 | 在 `core/nodes/` 注册终端执行和 Git 操作描述；`core/connect.ts` 管理资源引用、工具引用和接续触发。Host 解析固定值、模板、上游提供、AI 生成和人工填写。通过 `agent/pre-step` 加入提示，并条件注册提供参数的工具，按上游回合与目标节点存入参。缺失按上游、AI、人工顺序解决，模板和追问作为可配置途径。模板值作为参数传递，shell 模式依所选 shell 转义。 | 两种线型按各自语义执行。两个下游的同名参数互不串用，缺失必填项进入可编辑的放行框。恶意格式的提示词只作为参数值，终端验收使用本地无副作用的命令。 |
| P4.2 确认与执行 | 在 Host 固化命令、参数、工作目录、直接来源会话和 Git 修订号。固定值按 E37 执行，来自上游或 AI 的值默认等待确认，白名单比对完整操作。直接来源的完全访问模式从原生会话策略读取。一次性命令使用 `ctx.subprocess`，收集退出码、stdout、stderr、耗时和超时。Git 使用 `HostGitService` 和 `GitActionRequest`，按任务要求确认 discard、push、删除 worktree 与多会话切换分支。命令与 Git 结果走成功或失败出口，长输出沿用 P2 的 spill。 | 隔离工作区验证参数预取、取消、超时、非零退出、Git 暂存和修订冲突。冷重启恢复待确认记录，已启动的副作用标为需检查的中断状态。一次确认只触发一次执行。 |
| P4.3 交互终端与观测 | 核实 rc.3 发布包中的原生终端控制通道。交互执行向已绑定的长期终端发送命令，通过结束标记或输出匹配完成；获取并释放客户端或 Host 侧 attach 所需的通道。从原生 Session 工具事实派生已有终端和 Git 节点的系统观测线，展示最近调用。作用域限制选项使用原生可用的工具过滤入口。 | 长期运行的进程输出就绪标记后推进下游，进程仍可查看。历史 Session 与实时 Session 产生相同观测事实，线不可编辑。工具过滤只影响选择该选项的会话。 |
| P4.4 检查器与执行卡片 | 复用 `client/ToolNodeViews.tsx`、`ConfigForm`、`InspectorPanel`、`PayloadPeekCard`。按照 §3.6-J、M 展示命令及参数、审批、状态、退出码和结果。状态模型在本阶段记录，顶部状态端口接入 P5 共用体系。 | 编辑操作和布线不会执行。执行前能查看完整实参，运行后可查看输出和重复执行提示。四种视图与原生观测线均验收。 |

发布版的 Bash 和 PowerShell 沙箱都是 `ctx.shell` 的可替换执行器，依赖当前 profile 的沙箱提供者和策略。选项以启动时可验证的服务能力为准。直接子进程路径使用 E37 的确认规则。若交互终端的发布版接口只支持客户端 attach，则使用现有原生终端通道，Host 仍持有作业生命周期及退出判断。接口能力实测与选择结果随 P4 验收记录交付。

## P5 人工、触发与事件

对应 E21–E27、E31–E32、E41–E42。

| 任务 | 改动与实施顺序 | 验收 |
| --- | --- | --- |
| P5.1 人工交互 | 用 P1 的人工等待恢复机制和 P4 的参数表单入口实现表单、评分、审阅。输入模式含文本、数字、下拉、布尔、1–5 分或点赞及评语、编辑上游内容。Host 记问题、答案、超时和输出；按设置走跳过、默认答案或超时分支。AI 预填为可确认的单次请求，默认关闭。按 §3.6-K 在卡片、视口边缘和运行总览提醒，扇出使用 `CanvasDialog variant="wide"` 批量操作。 | 单答和批答均验证合法字段、重复提交、改写输入与超时出口。重启后问题可继续作答。人工问答只出现在画布。打开、重绘和进入批量视图均产生零模型请求。 |
| P5.2 Host 触发调度 | 新增定时、间隔、文件变化、Git、终端、容器列和启动台触发器。用 `@deepseek-ai/dsh-util-time@0.2.2-rc.3` 的 `Cron` 和 `RRule` 计算日期，由 Host 登记并推进。持久化下次/上次触发、错过次数、去重键及挂起队列，支持冷却、每日上限和跳过/排队/打断。新增运行来源与节点 ID，以及画布全局默认和总闸。导入复用原对话框，启用触发器需显式勾选。 | 假时钟验证时区、有限 RRULE、冷却/上限、并发策略、重启漏跑计数及队列恢复。实际 Host 验证文件变化、Git、终端、看板移列触发以及启动台表单启动，文件列表可直接扇出。 |
| P5.3 状态端口与事件分发 | 在 `types.ts`、`core/connect.ts`、`host/storage.ts`、调度器和原生事件处理入口加事件边及信封。按线实现结束原因、状态切换、节流增量三种策略。默认携带摘要和原生 `sessionId + seq` 指针，按选项附完整快照并 spill。连续边的目标限定为无需模型的节点。Agent 目的线及环路在 Host 保存和运行入口校验冷却及次数上限。 | 等待、错误、完成与连续增量各自触发正确的目标。两个并发运行的事件不交叉。校验违规循环，测试有界的合法循环、事件去重与完整快照。 |
| P5.4 事件、消息线与通知界面 | 按 §3.6-E、F、L 修改 `client/geometry.ts`、`CanvasApp.tsx`、线路渲染和 `WorkflowImportDialog.tsx`。顶部菱形走现有端口显隐路径，事件线使用颜色语义及一次脉冲。原生消息线从几何中心走现有弧线，按需要裁去卡片内段，同步 `docs/design.md` §3.2。通知节点复用 rc.3 Workspace Toast Factory 与已验证的发布入口，浏览器授权后提供系统通知，提示音由用户启用。 | 色彩、边宽和低缩放符合第 3 节。缩放、折叠和消息计数更新正常。应用内通知可关闭，系统通知权限拒绝时应用内提示仍可用。运行总览可以过滤触发来源。 |

`dsh-util-time` 已随 DSH 锁在 0.2.2-rc.3。P5 需要从 FlowSpace 显式引用它，拟在本包声明同版本直接运行时依赖，继续用已发布的原生解析器。依照原计划单独确认这一项。rc.3 的 `workspace.toast` 声明为按业务键渲染的插槽，另有共享的 `workspace.toast.content` 工厂。以实际客户端验证可用的发布入口，若插槽只消费原生业务通知，直接复用该工厂呈现 FlowSpace 通知。

## P6 回放、调试、预算与玩法

对应 E43–E48。

| 任务 | 改动与实施顺序 | 验收 |
| --- | --- | --- |
| P6.1 回放 | 从 `run.graph`、已有令牌时间戳、步骤状态、变量历史及事件组装只读时间线。补齐缺失时间戳的兼容读取，在 `RunOverviewDock` 位置添加 §3.6-O 回放条、播放、拖动和 1× / 4× / 16×。镜头跟随当前执行节点，退出恢复用户原有视角。 | 改动现用画布后回放仍显示运行时拓扑，前后拖动可查看跳过、人工等待与变量值。回放不产生 Host 写入、模型请求或终端执行。 |
| P6.2 断点 | 在 `core/scheduler.ts` 的入队路径冻结完整来源、任务、可用工具和变量，在下发前保存暂停点。提供继续、单步和跳过，输入改动仅绑定本次步骤。使用已有等待提示和载荷预览，按 §3.6-P 加标记。 | 第一个断点命中时原生请求数为 0。单步只发送该步，之后在下一节点前停住。跳过向下游交付跳过令牌。重启后可查询同一输入并继续。 |
| P6.3 预算 | 在画布设置与节点检查器加入 token、时长和轮数上限。Host 汇总 DSH 步骤和单次模型用量，在调度及运行中判断限额，超预算时停止继续派发并发状态事件。计入已产生的并发用量，回放显示最终记录。顶栏按 §3.6-Q 展示实时消耗。 | 覆盖三类限额和两种作用范围、边界前后的并发运行、暂停到明确继续及事件去重。P2 的 AI 变换和 P4 参数生成均可计量。 |
| P6.4 玩法基础件与模板 | 扩展 `core/fanout.ts`、`core/runFanout.ts` 和描述配置，把条目字段绑定到泳道的模型、人设和工作目录。合并支持 AI 或人工分数择优，保留评分来源、并列顺序及未采用结果。复用常量节点，注册带种子的随机和轮询节点。通过 `client/templates.ts` 交付模型擂台、模型陪审团、辩论、头脑风暴墙、随机灵感五个模板。 | 同一 seed 可重现选择，轮询跨重启保留位置。择优稳定处理同分、无效分数和乱序。五个模板可从内置入口导入并按各自预置流程运行。擂台可使用不同 mock 模型提供的实际会话路由。 |
| P6.5 战绩榜与战报 | 在 Host 存储按运行去重的擂台胜负结果，按模型和任务标签查询。运行结束后以单次模型请求生成战报，持久化时长、用量、轮数、最佳节点及产出物。按 §3.6-R 复用 `ModelChip`、表格、`CanvasDialog` 和产出物列表。图片导出从同一战报正文生成 PNG。 | 复跑和重启不重复计胜负，同分按已记录的排名处理。标签过滤、失败反馈、战报生成与下载在实际浏览器验证。截图与导出图片显示相同指标和产出物。 |

最终使用 Mock 模型验收所有新增执行链路，在博物馆沙盒增量加入展区，核对已有画布与开馆快照，再以构建包启动本机服务。
